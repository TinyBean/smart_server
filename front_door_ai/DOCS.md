# 安装与配置

## 1. 安装 add-on

将本仓库的 `front_door_ai` 目录复制到 HA OS 的 `/addons/front_door_ai`，
在应用商店刷新本地应用，选择 **Front Door AI** 并构建安装。
首次构建需要访问 Debian、PyPI 和 Intel 模型存储；阿里千问模式在生成新音频时需要互联网。
复制目录或制作发布包时须包含 `requirements-runtime.txt`；它由锁文件生成，包含生产依赖版本与哈希。
后续仅修改应用版本或业务代码时，构建会复用依赖和模型层。首次使用新分层仍需建立缓存，
依赖或基础镜像变化、缓存被清理后也会重新下载。维护与验证命令见仓库 README 的「镜像构建缓存」。
也可以在你将本仓库发布到 Git 后，通过仓库地址添加应用源。

目标是 HA OS 的 amd64 Supervisor 环境。Dockerfile 基于 Debian/glibc，
直接安装锁定的 Python wheels，使用独立 CPU 推理，无 GPU/宿主设备权限。

## 2. 配置连接

在 add-on 配置页面填写：

| 参数 | 示例 / 含义 |
|---|---|
| `camera_url` | `http://192.168.1.50/stream`，ESP32 的 MJPEG 流 |
| `mqtt_host` / `mqtt_port` | `core-mosquitto` / `1883` |
| `mqtt_username` / `mqtt_password` | Broker 已配置的用户与密码 |
| `mqtt_tls` | 使用系统信任 CA 校验的 TLS，默认 false |
| `mqtt_prefix` | `home/frontdoor`，必须与固件、自动化一致 |
| `device_id` | `frontdoor`，用于稳定 MQTT Discovery 标识 |
| `public_base_url` | `http://192.168.1.10:18080`，ESP32 可访问的 HA 主机地址 |
| `todo_entity` | `todo.departure_reminders` |
| `tts_provider` | `qwen` 使用阿里千问；`piper` 使用本地音色 |
| `qwen_api_key` | 千问平台 API Key（密码输入项） |
| `qwen_tts_url` | 默认 `wss://cn-beijing.maas.qianwenaiapi.com/api-ws/v1/inference` |
| `qwen_tts_model` | `qwen-audio-3.1-tts-flash` |
| `qwen_tts_voice` | `longjielidou_v3.1`（龙杰力豆） |
| `piper_model` | `/config/piper/voice.onnx` |
| `detector_model` | `/models/person-detection-retail-0013.xml`，镜像内置 |

`public_base_url` 使用局域网可达地址，不能使用容器内部 DNS 名称。
8080 映射到主机 18080，提供局域网只读媒体访问；管理操作仅走 Ingress 8099。
连接配置修改后重启 add-on。日志和管理设置不会输出密码及 HA 令牌。

## 3. 语音合成

### 阿里千问（qwen）

在应用的「配置」中选择 `tts_provider: qwen`，填写「阿里千问 API Key」，保存并重启应用。
模型使用 `qwen-audio-3.1-tts-flash`，龙杰力豆音色使用 `longjielidou_v3.1`。
默认地址对应[千问平台模型页](https://www.qianwenai.com/models/qwen-audio-3.1-tts-flash)提供的北京接口，
请使用与接口匹配的 API Key。百炼业务空间用户可以填写对应地域的
`wss://<WorkspaceId>.cn-beijing.maas.aliyuncs.com/api-ws/v1/inference`；新加坡使用
`wss://<WorkspaceId>.ap-southeast-1.maas.aliyuncs.com/api-ws/v1/inference`。
音色名称参见[官方音色列表](https://platform.qianwenai.com/docs/developer-guides/speech/voice-list/qwen-audio-tts)。

合成时会将播报文案及选用的待办正文发送给阿里平台。密钥只用于服务鉴权，不写入缓存键、管理页面、MQTT 状态或日志。
本地开发也可通过 `DASHSCOPE_API_KEY` 环境变量提供密钥；HA 优先使用配置项。
合成成功后保存到本地 WAV 缓存，待办、模型、音色和参数未变化时不重复请求云端；
点击「重新生成」会重新调用接口。整段输出仍为 16 kHz、单声道、16 位 PCM WAV，最长 180 秒。
收到完整成功回执后才发布音频缓存；断线、超时、鉴权失败和不完整音频均不能完成待办。
未填写密钥时，提醒页面会显示填写提示；摄像头、检测与设备固定语音仍可工作。

### 本地 Piper（piper）

选择 `tts_provider: piper`，在 HA 的 `/addon_configs/local_front_door_ai/piper/` 下放置 Piper 音色：

```text
voice.onnx
voice.onnx.json
```

从 Git 仓库安装时，路径中的 `local` 替换为该仓库标识。
保留匹配的 ONNX 和模型 JSON，查看所选音色的模型说明。
来源：https://huggingface.co/rhasspy/piper-voices ，中文音色可在 `zh/zh_CN` 中查找。
音色未提供时视觉功能照常运行，提醒页面显示合成不可用。
合成结果统一转换为 16 kHz、单声道、16 位 PCM WAV，最长 180 秒。

## 4. 区域标定

打开 add-on 的 Web UI → 摄像头与区域，依次选择室外、过渡、室内并点击画面绘制。
区域内部不能重叠，建议相邻区域共享边界，避免判定点穿过缝隙时中断迁移。
默认以人体框底边中心为观察点。若镜头只能看到半身，底边会贴在画面底部，
请在检测设置中选择「人体框中心（半身画面）」，并按预览中的黄色判定点确认区域与行走方向。
橙色判定点标为「区域外」，即使人体框覆盖了彩色区域，也不会计为进入该区域。
保存后立即重置旧轨迹，并使用新区域。
未保存三个有效区域前，不发布三区域迁移事件；下方的出门路线可独立启用。

参数默认：5 FPS 检测、0.5 激活置信度、0.5 秒最短轨迹、5% 对角线位移、5 秒每轨迹冷却。
从 1.1.9 起，人体检测同时使用原始视图和带留边的缩小视图，改善近距离半身、背影被画面截断时的漏检。
两次结果映射回原画面并去重后再跟踪，不降低轨迹和事件的置信度门槛；实际帧率以运行概览为准。
参数通过 Ingress 修改，保存在 `/data/config.json`；不在 Supervisor 选项中重复定义。
跨到目标区域时若置信度短暂下降，系统最多等待 1.5 秒确认；仍须达到配置的置信度。
超时、回到起始区域、离开所有区域或失去可靠观测会取消待确认事件。

### 从摄像头旁出门（1.1.8）

适用于从画面下方、摄像头旁斜向走向门口，未能完整经过「室内 → 过渡 → 室外」的路线。

1. 半身画面先在「检测设置 → 区域判定点」选择人体框中心并保存。
2. 在「摄像头与区域 → 正在绘制」选择「出门路线 CAMERA → DOOR」。
3. 按预览中人体判定点的实际位置，先点摄像头旁起点，再点门口终点，形成红色箭头。
   起点应选在人已能稳定被检测的位置，终点应选在能确认出门的位置。无需紧贴画面边缘。
4. 点击「保存区域与路线」启用。可以保留原三区域，路线允许穿过或位于区域外。
   清除路线并保存即可停用；旧配置升级后默认停用，需自行标定。

系统要求同一轨迹从箭头前 20% 行进至后 20%，至少三次观测，满足最短轨迹时间、
最小位移与置信度。路线容差默认是画面对角线的 6%，页面显示红色参考带；
可在检测设置中调整，过大容易包含附近无关的通行轨迹。轻微弯曲路线可以用容差覆盖。
反向、只在终点出现、停留及走到一半折返不会触发。明显偏离路线、超过 8 秒或丢失跟踪会取消本次行程。
到达终点后最多等待 1.5 秒恢复置信度；触发后须回到起点才能再次触发，并遵守原有单轨迹冷却。
这一路线只产生 EXIT，与三区域共用去重和原有 HA 出门播报流程，两种进门模式均可使用。
事件记录会标注「摄像头旁出门」，截图中保留红色方向箭头。

图片只能辅助规划，实际参数应通过固定机位的真实行走验证；仅有图片不能验证跟踪连续性。

## 5. HA 摄像头与自动化

在 HA 添加 **MJPEG IP Camera**：

- MJPEG URL：`http://HA-IP:18080/stream`
- Still image URL：`http://HA-IP:18080/snapshot`

HA 从 add-on 获取画面，ESP32 只接受 add-on 的一条常驻视频连接。
配置 MQTT 集成后，Discovery 自动创建 Activity、人数、输入帧率、提醒数及缓存就绪实体。
实际 entity_id 以 HA 自动分配的结果为准。

如需附带待办，创建 Local To-do，设定 entity_id 为 `todo.departure_reminders`，加入提醒。
将仓库 `examples/ha_automations.yaml` 中的自动化复制到 HA 自动化编辑器，
并按实际前缀调整 Topic。自动化直接订阅实时 MQTT 事件，避免 HA 重启后恢复实体状态触发播放。
**只安装一份出门播放自动化**；HA 决定何时发起，后端不会自行消费 EXIT 并播放。

ENTER 向 add-on 请求 `play_arrival`，播放预缓存欢迎语；未就绪时使用固件本地 `welcome`。
EXIT 向 add-on 请求播放出门提醒。升级时替换原 ENTER 分支，避免同时播放两段欢迎语。
在「进出门播报」页面分别编辑进门欢迎语、出门提醒及启用开关，保存后自动合成并预缓存。
出门默认「出门别忘了带手机和钥匙。」，没有待办也会播放保存的文案。
「附带 Home Assistant 待办事项」默认启用，沿用原有待办流程；关闭后只播报编辑的文字，
无需读取 HA 待办列表，也不会为这次纯文字播报完成待办。
启用时，文案与待办一起合成，例如「出门别忘了带手机和钥匙。提醒你：带雨伞，还有取快递。」。
完整播报最多 1500 字。设置保存在应用数据库中，重启后保留；浏览器自动刷新不会覆盖未保存的编辑。
两个播报各自提供试听、重新生成和模拟按钮。浏览器试听不完成待办；模拟出门会在设备上真实播放，
成功后才完成该音频对应的待办。修改文案后须保存再模拟。

### 开门后人员出现（1.1.6）

需要 ESP32 1.3.1，以及更新后的进出播放自动化。页面「进出门播报」可修改欢迎语，
默认「欢迎回家。」；保存后使用同一语音服务、模型和音色合成。进门播报不会完成待办。
浏览器试听只在浏览器播放；「模拟进门」通过 HA 自动化在 ESP32 上播放，事件明确标记为模拟。

摄像头固定到最终位置后，在「摄像头与区域」绘制并保存门体观察区和门后人员出现区。
门体观察区应包含门框或门板纹理，避开容易被人体完全遮挡的位置；人员出现区应覆盖从门后
首次露出的人体中心，不要覆盖室内普通通行区域。它们允许相互重叠，也可与原三区域重叠。

先关闭门、让开门体区，采集关门参考；再打开门采集开门参考，可在几个开门角度重复采集。
每次采集约一秒，保留最多 12 张同类参考。重新采集关门参考会清除旧开门参考。
参考差异不足、画面过于平坦、被人体遮挡或检测未就绪时，需要重新调整和采集。
完成后在「检测设置 → 进门判定」选择「开门后人员出现」。未标定时不能启用此模式。

识别顺序为稳定关门 → 稳定开门 → 新人体从人员出现区出现。开、关门都需三次连续有效观测；
人体使用现有置信度与最小轨迹年龄，至少三次连续有效观测。首次符合时产生一条 ENTER，
不要求继续走入室内；本轮开门只触发一次，确认关门后重新等待。启动、断流及重新标定后
必须先看到关门。门被遮挡时显示「不确定」，不能单凭画面变化推断开门。
短时换号结合位置继承原人员来源；已有室内人员或来源冲突时不作为新进门。

新模式只替换 ENTER；EXIT 使用原三区域或已标定的出门路线。移动摄像头后必须重新标定。
固定机位的参考匹配不保证覆盖所有光照及遮挡情形，启用前需完成真实开关门和人员进出的验收。

数据库自动迁移至 schema 2。降级前恢复升级前的应用数据备份，不能让 1.1.5 直接写入新库。
整段音频播放成功后，才完成该批次待办。动态缓存未就绪时播放设备本地 `goodbye`，待办保留。
页面编辑的是合成文案；缓存不可用时使用的设备内置欢迎音、告别音保持固件设置。
关闭某一方向的播报后，该方向也不会播放内置提示音。

## 6. 运维

- Overview 区分摄像头、检测、MQTT、HA 和区域状态。Reminder 页面单独显示合成与缓存错误。
- `/healthz` 表示进程存活；`/readyz` 表示视觉、MQTT 和 HA 主链路就绪。缺少摄像头不会触发容器重启循环。
- 截图最多 7 天/500 条；未引用音频超过 7 天清理。修改保留策略在下一次清理周期生效。
- SQLite 使用 WAL 与 FULL 同步；冷备份包含事务与参数。媒体可重建，默认不进入 HA 备份。
- 播放回执超时后保留待办。24 小时内、且未被新播放批次替代的成功回执仍可提交。
- 网络恢复只恢复状态与缓存准备；旧进出事件和旧播放命令不主动补发。
- 相机/MQTT/HA 断线自动重连，最长间隔 30 秒。
- 人体模型加载失败显示具体模块未就绪；修正路径或文件后重启 add-on。

故障排查先检查配置、页面状态和 Logs；INFO 不记录每帧数据、音频内容或待办正文。
